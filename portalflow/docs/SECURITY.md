# Security

Implemented: Argon2id (64 MiB, 3 iterations, parallelism 1); hashed opaque tokens; HTTP-only access/refresh cookies; SameSite=Lax; mandatory HTTPS/secure-cookie validation in production; CSRF token validation and exact Origin allowlist; strict Zod bodies; Redis rate limits; tenant membership/role checks on every request; suspension; token expiry/one-use transactions; SMTP outbox; safe public identity projections; tenant audit events; Helmet/API and frontend security headers; non-root container runtime.

Email actions use URL fragments, which are removed from browser history when the page opens, and require explicit confirmation. Verification tokens last 24 hours, reset tokens one hour, invitations seven days. Password reset revokes every user session. Access tokens last 15 minutes and sessions 30 days. Refresh replay detection currently covers the preceding token, not arbitrary older generations. Session rotation has a compare-and-swap guard against concurrent reuse. Multi-tab refresh races may require signing in again.

Rate limits are 30 auth actions and 300 other requests per IP per minute. Proxies are not blindly trusted. The Next proxy currently groups API traffic under its network address; production must add a vetted proxy/IP strategy before broad deployment. Limiter failure denies requests. Body parsing uses Nest/Express's default size limit. JSON content validation is server-side.

Current limitations: no MFA, end-user account/data deletion/export yet, no automated retention job, no database row-level security, no platform-admin management, no full audit for every login event, no credential encryption/upload features because those modules do not exist yet. Frontend CSP allows inline scripts/styles required by the current Next setup; nonce-based CSP hardening is pending. This release is a development foundation, not a production security certification.

Customer message content is now stored in PostgreSQL when entered through simulation or agent replies. Redis notifications contain only tenant/conversation IDs, and logs omit bodies. No external API credentials are stored. Do not expose Mailpit or development database/Redis ports publicly. Production secrets belong in the deployment secret store. Never seed production. Expired/failed email outbox records need retention and redaction before a public launch.

Indian data-protection obligations require an appropriate notice, lawful processing basis, purpose limitation, retention, security, grievance handling and data-subject request process suited to the business. Meta additionally imposes consent, opt-out, template and messaging-window obligations. This software does not confer automatic legal or Meta compliance; seek qualified review before processing real customer data.


Messaging additions: composite tenant FKs, viewer write restrictions, consent history, STOP/UNSUBSCRIBE suppression, service-window checks at enqueue and delivery, idempotency keys, locked status transitions, and WebSocket authorization per emitted notification. WebSocket handshakes are rate limited to 30/IP/minute. Deleted contacts remain suppressed and hidden. Internal message processing currently holds database locks while calling the local provider; a live provider will require a lease/outbox strategy before network calls are enabled. Subscription quotas and Meta rate limits are not implemented because live sending is unavailable.

Bot additions: strict versioned graph validation, no arbitrary code execution, safe variable-name restrictions, 100-node/100-step limits, transactionally pinned versions and persisted waits, role checks on editor writes, and tenant-scoped execution/lead reads. Captured answers are customer data stored in PostgreSQL; retention/export/deletion controls remain incomplete. Published text is rendered as escaped React text in the UI. HTTP/AI/media nodes are absent until their security controls are implemented.

Platform administration uses a dedicated server guard in addition to global authentication. The flag is read from the database for every request; register/profile DTOs cannot set it. Tenant suspension revokes tenant sessions, and administrator workspaces cannot be suspended through the admin UI. Global plan/config changes use revision checks and append platform audits. Public branding has a strict allowlist of strings/hex colour; it cannot store or return integration credentials. Production admin bootstrap requires an existing verified account with an active workspace and explicit server-operator CLI access.
